# Customer dispatch

Run `alembic upgrade head` after updating the backend. This adds customers and customer-specific dispatch history fields. Existing marketing-person contacts and dispatch history remain available.

The **Marketing persons** page holds the people who receive bilty messages. The **Customers** page holds each customer's name, assigned marketing person, and optional phone number, city, and other information. A customer has one current marketing person; a marketing person can have many customers. Reassign a customer by editing it. A marketing person with active customers cannot be deleted until those customers are reassigned or deleted. Customer directory filters cover marketing person, city, and whether a phone number is present. **View messages** opens a customer conversation containing only sends addressed to that customer; customers without a number show **No number added** instead.

On **Dispatch**, search for a customer and select it. Compose opens the customer's dispatch conversation with the message box below it. The assigned marketing person is the default recipient. **Add recipient** beside the customer name opens a picker that includes the selected end customer, additional active marketing persons, and other customers with phone numbers. In live mode, the selected end customer requires a phone number. Up to 25 additional people can be selected. Each selected recipient gets one WhatsApp request and history record, including their name and ID. Duplicate selections and the default recipient are ignored by the API. History stores names at send time, so later reassignment does not change old records. Meta acceptance is recorded separately for each destination; acceptance is not delivery confirmation. If one destination fails, inspect its result before sending again, because another destination may already have been accepted.

## Sending modes

`WHATSAPP_SEND_MODE=test` is the default. Every selected marketing person generates one send to `WHATSAPP_TEST_RECIPIENT`; every selected customer generates one send to `WHATSAPP_CUSTOMER_TEST_RECIPIENT`. Set the latter to enable customer copies in test mode. The main customer's copy can be selected without a customer phone number in test mode; additional customers need a phone number to appear as eligible. Both test numbers must be eligible recipients in the Meta test setup.

`WHATSAPP_SEND_MODE=live` sends to the assigned marketing person's number and, when selected, the customer's number. Set valid `WHATSAPP_ACCESS_TOKEN` and `WHATSAPP_PHONE_NUMBER_ID` for a WhatsApp setup that can send to the intended recipients. Switch modes in the backend environment and restart it. The frontend displays the active mode before sending. A production-capable WhatsApp setup and recipient eligibility are required for Meta to accept real sends; changing the environment variable alone does not provide them.

Phone fields accept only 11–15 ASCII digits. Keep phone values as text so leading zeroes are preserved. Local numbers beginning with `0` use `WHATSAPP_DEFAULT_COUNTRY_CODE`, which defaults to `92`. Set that value to the relevant country code for your installation. Existing records with a leading `+` remain sendable; edited numbers are saved as digits only. The backend validates the resolved destination before submitting a send.

Customer APIs are under `/api/v1/customers/` and support paginated search, `marketing_person_id`, `city`, `phone_status`, create, update, and soft delete. `/api/v1/customers/filters` supplies the city choices. Customer dispatch APIs are `/api/v1/customer-dispatch/mode`, `/text`, and `/media`. All require the existing application login. Dispatch history supports `customer_id` for the whole dispatch conversation and `recipient_customer_id` for messages sent to one customer.

The History page requests `/api/v1/dispatch/history/page` with 20 records per page. To add sample Pakistani records to a development database after migrations, run `python -m app.scripts.seed_demo_data` from `backend` (or `docker compose exec backend python -m app.scripts.seed_demo_data`). The script adds 10 marketing persons and 30 customers marked **(Demo)**, and a second run does not duplicate them. Their phone numbers are fictitious; use test mode when exploring dispatches with this data.
